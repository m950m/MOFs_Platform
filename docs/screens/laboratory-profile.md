# Laboratory profile

What **your** laboratory can actually do — recorded by you, in four
visibly distinct statuses.

## What enters

Capability entries, each with:

- **Name** (e.g. argon line, hydrothermal reactor, glovebox).
- **Description / notes** (optional).
- **Status** — one of exactly four:
    - **current — available now**
    - **future — planned, NOT currently available**
    - **explicitly unavailable**
    - **`unknown` — not yet confirmed** (the honest default for new entries)

Corrections are made on the same screen: pick an entry, edit, save with a
reason-able attribution; the correction is attributed and the old value stays
in history.

## What comes out

The recorded capability list — nothing more. The profile is what the
[Lab fit](lab-fit.md) screen compares candidate requirements against.

## Honest markers

- `current` ≠ `future` ≠ `explicitly unavailable` ≠ `unknown`: each entry
  shows exactly the status that was entered.
- **Nothing is seeded.** The tool invents no equipment, no restrictions, and
  no defaults — an empty profile stays empty until you record it.
- The profile implies **no candidate suitability, no synthesis success, and
  no material restriction**. It never infers a blanket exclusion (the tool
  will not decide for you that "material X is impossible in this lab").
- Reconfirm the profile before trusting a fit assessment — old notes about
  what the lab lacked are not universal material facts.
